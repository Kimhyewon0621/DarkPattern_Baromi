# AI 검토 후보 라벨링 지침

이 지침은 기본 진단 엔진이 확정하지 못해 유료 AI 검토로 넘긴 후보를 운영자가 라벨링할 때 사용한다. 라벨은 법적 판단이나 쇼핑몰의 위법 확정이 아니라, 저장된 증거가 특정 다크패턴 신호를 얼마나 뒷받침하는지에 대한 데이터셋 라벨이다.

## 허용 라벨

| 라벨 | 사용 기준 |
| --- | --- |
| `LIKELY_RISK` | 증거가 후보 설명과 일치하고, 사용자에게 불리한 선택·비용·정보 비대칭이 화면/상태 변화로 재현된다. |
| `NEEDS_REVIEW` | 의심 신호는 있으나 필수성·가격·맥락·사용자 의도를 증거만으로 확정할 수 없다. |
| `LIKELY_BENIGN` | 후보와 비슷한 표현이 있지만 무료·선택 가능·사전 공개 등 반대 증거가 확인된다. |
| `INSUFFICIENT_EVIDENCE` | 화면 접근 실패, 인증/OTP/CAPTCHA, 증거 누락 등으로 판단에 필요한 사실을 확인하지 못했다. |

## 라벨링 순서

1. `candidateId`, 유형, 단계, 후보 설명을 먼저 읽는다.
2. 연결된 `evidenceIds`의 DOM/스크린샷/가격 원장/옵션 상태만 확인한다.
3. 화면에 실제로 보인 사실과 운영자의 추론을 분리해 메모한다.
4. 네 가지 라벨 중 하나를 선택하고, 근거 증거 ID를 최소 하나 남긴다.
5. 증거가 부족하면 위험으로 추정하지 말고 `INSUFFICIENT_EVIDENCE`를 선택한다.

## 유형별 핵심 확인점

- 사전선택: 유료 옵션인지, 기본 선택인지, 해제 시 총액이 감소하는지
- 순차공개 가격: 앞 단계에서 가격·필수 비용이 공개됐는지, 뒤 단계에서 새로 붙었는지
- 긴급성·희소성: 실제 재고/기한 증거가 있는지, 단순 문구인지
- 중요 정보 축소·누락: 구매 결정에 필요한 조건이 눈에 띄지 않게 숨겨졌는지
- 해지·탈퇴 방해: 가입보다 불필요하게 많은 단계·반복 확인·대체 경로가 있는지
- 추천·인기·후기: 근거·출처·광고 표시가 있고 선택을 부당하게 유도하는지

## 합의 데이터셋 기준

- 각 후보는 서로 독립적인 라벨러 2명이 먼저 판정한다.
- 라벨이 다르면 제3 라벨러가 증거만 보고 최종 라벨을 결정한다.
- 최종 라벨과 함께 `labelSource`, 라벨러 수, 근거 증거 ID, 라벨링 시각, 규칙 버전을 저장한다.
- 동일 후보를 재라벨링할 때 이전 라벨을 덮어쓰지 않고 버전별 레코드로 보존한다.
- 운영 라벨이 없는 행은 모델 평가의 정확도·정밀도·재현율 계산에 포함하지 않는다.

## 품질 게이트

모델 교체나 파인튜닝을 결정하기 전 고정 평가셋에서 다음을 유형별로 확인한다.

- `LIKELY_RISK` 정밀도·재현율
- `NEEDS_REVIEW` 비율과 미판정률
- `INSUFFICIENT_EVIDENCE` 오판율
- 평균·p95 지연시간과 요청 비용
- 라벨러 간 일치율 및 불일치 사례

운영 라벨이 충분하지 않으면 모델을 선택하거나 성능이 개선됐다고 주장하지 않는다. `datasets/labels.example.jsonl`은 형식 예시일 뿐 실제 평가 데이터로 사용하지 않는다.
