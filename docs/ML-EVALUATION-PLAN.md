# 바로미 탐지 성능·학습 계획

## 원칙

바로미는 학습 모델을 먼저 넣는 제품이 아니다. 관측값을 안정적으로 수집하고, 규칙으로 확정 가능한 판정을 규칙으로 처리한 뒤, 모호한 후보만 분류기나 LLM에 보낸다. 딥러닝은 새로운 시각·구조 유형이 규칙과 경량 분류기로 충분히 처리되지 않을 때만 검토한다.

## 쇼핑몰 데이터셋 분리

- **개발/테스트 세트**: 규칙과 수집기 개발에 사용한다.
- **학습 세트**: 사람이 라벨링한 관측값으로 사전·경량 분류기를 개선한다.
- **검증 세트**: 개발자가 결과를 보지 않고 릴리스 후보를 평가한다.
- 같은 쇼핑몰의 PC·모바일·재실행 흐름은 같은 그룹으로 묶는다. 화면 단위로 무작위 분할하지 않아 누수를 막는다.

검증 세트는 학습·규칙 튜닝에 다시 사용하지 않는다. 쇼핑몰 스킨이 바뀌면 새 그룹으로 기록한다.

## 단계별 판정

1. 결정적 규칙: 체크 상태, 해제 전후 총액, 가격 원장, 화면/API 일치 여부.
2. 사전·정규화: 배송비·포장비·수수료·마케팅·자동연장 문구.
3. 경량 분류기: 상품 옵션과 부가서비스처럼 문맥이 필요한 텍스트의 **후보 종류**를 태깅한다. 현재 `FEE`·`PAID_OPTION`·`FLOW` 라벨은 위험 여부나 AI 호출 필요성을 판정하지 않는다.
4. LLM 검토: 기본 보고서가 생성된 뒤 사용자가 요청한 경우, 규칙으로 사실을 확정하지 못한 후보를 연결 증거와 함께 추가 검토한다. 경량 분류기의 후보 종류만으로 후보를 제외하지 않는다.
5. DL: 시각적 강조·배치·복합 인터랙션을 추가할 때만 별도 실험.

## 첫 가설

- H1: 화면 금액과 가격 API를 함께 확정할 때 순차공개 가격 오탐률이 감소한다.
- H2: 옵션 해제 전후 총액 차이를 사용하면 유료 사전선택 재현율이 증가한다.
- H3: 목록·배너 가격을 가격 원장 0단계로 포함하면 늦은 비용 공개 판정의 재현율이 증가한다.
- H4: 탐색 반복 일치율이 낮은 쇼핑몰에서는 모델 개선보다 수집기 개선이 전체 성능을 더 크게 높인다.

각 실험은 가설, 데이터셋 버전, 규칙/모델 버전, 호출 비용, 정밀도·재현율·정상 상점 오탐률·탐색 성공률을 함께 기록한다.

## 릴리스 게이트

- 검증 세트는 학습에 사용되지 않았는가
- 위험 사례별 증거 ID가 존재하는가
- 상점 그룹 단위로 지표를 계산했는가
- 탐색 실패와 정상 판정을 분리했는가
- 규칙 변경 전후의 오탐·미탐 차이를 확인했는가
- LLM/DL 호출률과 비용이 예산 안에 있는가

평가 명령은 `npm run evaluate`로 실행한다. `npm run evaluate -- --help`는 평가를 실행하지 않고 사용법만 출력하며, `--text-validation`을 붙이면 문구 변형 검증 세트를 선택한다.

상점 그룹별 데이터 품질과 미검사 범위는 `npm run dataset:groups`로 확인한다. `BAROMI_DATASET_PATH`로 평가 파일을 바꿀 수 있으며, `PENDING` 라벨은 합의 지표에서 제외된다. 릴리스 게이트는 그룹이 split을 넘나들지 않고, 합의 라벨이 하나 이상이며, 그룹별 분포를 확인한 뒤 통과시킨다.

문맥이 제한된 후보를 AI에 보내기 전의 결정적 1차 분류기는 `npm run classifier:evaluate`로 회귀 평가한다. 현재 기준선은 비용·옵션·표면 흐름·미검증 흐름의 **후보 종류**를 분리한다. 이 출력은 규칙상 확정 결과가 아니므로 `UNRESOLVED`만 AI에 넘기는 필터로 사용하지 않는다. 이 평가는 합성 회귀 게이트이며, 운영 라벨 데이터의 모델 선택 지표를 대체하지 않는다.

## 현재 구현의 한계

- 위험 유형을 문구 키워드만으로 붙이던 후보 탐지기는 제거했다. 텍스트·체크 상태·가격은 유형을 추정하지 않은 증거 후보로 보존하며, 의미 판단은 근거가 연결된 규칙이나 사용자가 요청한 AI 검토에서 다룬다. 화면 단계와 표면을 찾는 탐색 휴리스틱 및 통화·비용 텍스트 파서는 별도 작업으로 남아 있어 다국어·스킨별 검증이 필요하다.
- 페이지·깊이·시간 예산은 안전 제한이다. 큐가 예산 안에서 빌었을 때만 크롤러 완료로 기록하며, 안전상 제외한 결제·계정 변경 경로와 접근 불가 경로는 “사이트에 없음”으로 취급하지 않는다.
- 확인 가능한 DOM·가격·선택 상태는 규칙으로 기록한다. 실제 수치의 진실성, 광고/추천의 적정성, 시각적 압박, 해지의 실질적 난이도처럼 화면만으로 확정할 수 없는 판단은 `REVIEW_NEEDED` 또는 `NOT_TESTED`로 남기고 사용자 요청형 AI의 보조 검토 대상으로 삼는다.
- 따라서 `NOT_OBSERVED`는 관련 표면의 실제 증거를 검사한 유형에만 사용한다. 전체 크롤링 완료 표시는 16개 모든 유형의 의미 판정 완료를 뜻하지 않는다.
